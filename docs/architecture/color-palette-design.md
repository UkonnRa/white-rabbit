# Color Palette Design (ARCHIVED)

> **Superseded by Nuxt UI migration.** See `docs/adr/0008-nuxt-ui-migration.md`.
> The multi-theme system described below has been removed. Theming now uses
> Nuxt UI's built-in Tailwind-based palette configured in `app.config.ts`.

## Problem (Historical)

If both `tailwind-default` and `md3-expressive` use the same MD3
`SchemeTonalSpot` algorithm to derive colors from a seed, the only remaining
difference is corner radius and interaction patterns. The themes converge
visually — tailwind-default becomes "MD3 with square corners." A meaningful
multi-theme system requires that color palette **structure** differs, not just
the values plugged into the same slots.

## What Makes Each Approach Unique

### Material Design 3: Single Seed → Harmonious Derivation

MD3's color system is **maximally derived**. One seed hex produces the entire
palette through the HCT (Hue-Chroma-Tone) perceptual color space:

- **Primary, Secondary, Tertiary** are all mathematically derived from the seed.
  Secondary shifts the hue ≈60°, tertiary shifts ≈120°. The designer controls
  _one_ input; the algorithm controls everything else.
- **Tonal palettes** (T0–T100) for each role provide the light/dark variants.
  Light mode picks from the bright end; dark mode from the dim end.
- **Surface container hierarchy** (lowest → low → default → high → highest) is
  a five-step neutral ramp tinted toward the primary hue.
- **"on-\*" contrast colors** are a first-class concept: every fill color has a
  dedicated text-on-fill color guaranteed to meet contrast ratios.
- **Error, tertiary-container, inverse-surface** etc. are all part of one
  coherent system with 29+ named color roles.

**Uniqueness:** Enforced harmony. You cannot have a blue primary with an
unrelated orange secondary — the algorithm won't produce that. The palette
feels unified and "designed" even with arbitrary seed input.

**Trade-off:** Rigid. Designers lose independent control over secondary and
tertiary. The palette can feel "samey" across different seeds because the
hue-shift formula is fixed.

### Tailwind / shadcn / Radix: Independent Scales, Designer Picks

The Tailwind ecosystem (including shadcn/ui, Radix Colors, and Headless UI
patterns) uses a fundamentally different model:

- **Color scales are independent.** `blue-50` through `blue-950` is one scale.
  `slate-50` through `slate-950` is another. They are not derived from each
  other.
- **Primary = one scale, neutral = another.** A typical shadcn theme picks
  `zinc` for surfaces and `blue` for primary. Changing primary to `violet`
  doesn't affect the neutral ramp at all.
- **No enforced harmony.** The designer freely picks primary, secondary (if
  any), and destructive colors. They can be complementary, analogous, or
  clashing — that's a design choice, not an algorithm's job.
- **Dark mode = shade inversion.** Light mode uses `primary-600` for buttons;
  dark mode uses `primary-400`. Same scale, different index. Surfaces flip from
  `slate-50` → `slate-950`.
- **Fewer color roles.** shadcn defines: background, foreground, card, popover,
  primary, secondary, muted, accent, destructive, border, ring. That's ~11
  roles vs MD3's 29+. No surface container hierarchy, no tertiary, no tonal
  palettes.
- **oklch / HSL for generation.** Scales can be generated by stepping lightness
  in oklch at a fixed hue+chroma, or hand-tuned per shade.

**Uniqueness:** Designer freedom. You can pair a warm amber primary with cool
slate surfaces — impossible in MD3's derived model. The palette feels
"curated" rather than "computed."

**Trade-off:** No automatic harmony. Bad color picks produce bad palettes.
The system trusts the designer.

### Radix Colors (Notable Sub-variant)

Radix Colors deserves special mention because it occupies a middle ground:

- **12-shade functional scales** (1–12), not Tailwind's 11-shade (50–950).
- **Each shade has a semantic role:** 1–2 backgrounds, 3–5 interactive
  surfaces, 6–8 borders, 9–10 solid fills, 11–12 text.
- **Automatic dark mode pairing:** Every light scale has a named dark
  counterpart (`blue` → `blueDark`), hand-tuned per shade rather than
  algorithmically flipped.
- **P3 gamut aware.**

### Ant Design / PrimeVue

- **Ant Design** generates a 10-shade palette from a seed using Bezier curve
  interpolation in HSV space (not HCT). Less perceptually uniform than MD3,
  but still algorithmic. Neutral ramp is independent.
- **PrimeVue** uses three token tiers: primitive (raw scales), semantic (role
  mappings like `primary.color`, `surface.0`–`surface.950`), component
  (per-component overrides). Its Aura/Lara/Nora presets swap all three tiers.

## Design Decision for White Rabbit

### Structural Gap

| Dimension    | `md3-expressive`                                           | `tailwind-default`                                                                  |
| ------------ | ---------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Derivation   | Single seed → full palette via HCT                         | Seed picks a hue for primary scale; surfaces stay on an independent neutral scale   |
| Secondary    | Derived from seed (hue-shifted)                            | Fixed neutral — no colored secondary                                                |
| Tertiary     | Derived from seed (hue-shifted)                            | Not present (falls back to secondary)                                               |
| Surface ramp | 5-level container hierarchy, tinted toward primary         | 2-level (surface / surface-variant) from neutral scale, no primary tint             |
| Color roles  | 29+ (primary-container, on-tertiary, inverse-surface, ...) | 14 base-tier only (primary, secondary, surface, error, outline + their on-\* pairs) |
| Dark mode    | Tonal palette tone flip (T80→T20 etc.)                     | Scale index flip (shade-600→shade-400, neutral-50→neutral-900)                      |
| Harmony      | Enforced by algorithm                                      | Curated by scale choice                                                             |

### Seed Color Behavior Per Theme

**md3-expressive:** Seed hex → `SchemeTonalSpot` → all 29+ tokens derived.
Changing the seed changes _everything_ — primary, secondary, tertiary,
surfaces (tinted), containers. This is the existing behavior.

**tailwind-default:** Seed hex → extract hue → generate an oklch primary scale
(11 shades at that hue). Map specific shades to `--wr-primary` and
`--wr-on-primary` based on mode. Surfaces stay on a fixed neutral scale
(slate-like). Secondary maps to a neutral mid-tone. Error stays fixed red.

This means:

- In MD3, changing seed from purple to teal changes the entire mood — surfaces
  get a teal tint, secondary shifts, containers change.
- In tailwind-default, changing seed from purple to teal changes only the
  accent color — buttons, links, focus rings turn teal, but surfaces stay
  clean neutral gray. The app feels "the same but with a different accent."

This is the authentic behavior difference users expect from these two design
traditions.

### Implementation: oklch Scale Generation

For tailwind-default, generate a primary scale from a seed hue:

```text
shade   lightness   chroma
 50     0.97        0.02    (near white, subtle tint)
100     0.93        0.04
200     0.87        0.08
300     0.78        0.12
400     0.68        0.16
500     0.58        0.18    (mid-tone)
600     0.50        0.20    (light-mode primary fill)
700     0.42        0.18
800     0.34        0.14
900     0.27        0.10
950     0.20        0.06    (near black, deep tint)
```

Light mode: `--wr-primary` = shade 600, `--wr-on-primary` = white.
Dark mode: `--wr-primary` = shade 400, `--wr-on-primary` = shade 950.

Surfaces use a fixed neutral scale (chroma ≈ 0.01, hue 260):

- Light: surface = neutral-50 (0.99), background = neutral-25 (0.98)
- Dark: surface = neutral-900 (0.20), background = neutral-950 (0.16)
